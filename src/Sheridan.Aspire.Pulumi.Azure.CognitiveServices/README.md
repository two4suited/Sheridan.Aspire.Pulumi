# Sheridan.Aspire.Pulumi.Azure.CognitiveServices

_Azure OpenAI (Cognitive Services)_ — part of [Sheridan.Aspire.Pulumi](../../README.md).

`Sheridan.Aspire.Pulumi.Azure.CognitiveServices` ports `Aspire.Hosting.Azure.CognitiveServices` (the official package only ships `AddAzureOpenAI`). `builder.AddPulumiOpenAI("openai")` (aliases `AddPulumiAzureOpenAI`, `AddPulumiCognitiveServices`) provisions an `azure-native:cognitiveservices:Account` of kind `OpenAI` (S0, local auth disabled, public access enabled), matching the generated Bicep. `AddDeployment("chat", "gpt-4o", "2024-08-06")` adds a model deployment (`WithProperties` sets `DeploymentName`, `SkuName`, `SkuCapacity`; defaults Standard / 8, deployments are chained with `dependsOn` as in the official Bicep). `WithReference(openai)` or `WithReference(deployment)` grants the hosting compute environment's identity *Cognitive Services OpenAI User*; `WithRoleAssignments(openai, AzureOpenAIRole.…)` replaces that. Connection strings are `Endpoint=<endpoint>` / `Endpoint=<endpoint>;Deployment=<name>`. `ConfigureInfrastructure(infra => infra.CognitiveServicesAccount.Set("properties.publicNetworkAccess", "Disabled"))` edits the Pulumi resources (see `../../docs/provisioning.md`). The account name is auto-generated by the provider; the custom sub-domain is `<name><first segment of the subscription id>` (override with `CustomSubDomainName`) instead of Bicep's `uniqueString(resourceGroup().id)`. Not ported: private endpoint / network security perimeter association, `PublishAsExisting`.
