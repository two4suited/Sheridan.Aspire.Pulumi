# Sheridan.Aspire.Pulumi.Azure.ServiceBus

_Service Bus_ — part of [Sheridan.Aspire.Pulumi](../../README.md).

`Sheridan.Aspire.Pulumi.Azure.ServiceBus` ports `Aspire.Hosting.Azure.ServiceBus`. `builder.AddPulumiServiceBus("messaging")` (alias `AddPulumiAzureServiceBus`) provisions a Standard-SKU namespace with local auth disabled, matching the official Bicep (outputs `serviceBusEndpoint`, `serviceBusHostName`, `name`, `id`). `AddServiceBusQueue`/`AddServiceBusTopic`/`AddServiceBusSubscription` (plus the `AddQueue`/`AddTopic`/`AddSubscription` forms) and `WithProperties(...)` on queues, topics and subscriptions mirror the official API, including `Rules` (correlation filters) on subscriptions.

```csharp
var sb = builder.AddPulumiServiceBus("messaging").WithPulumiStack(azureStack);
sb.AddServiceBusQueue("orders").WithProperties(q => q.MaxDeliveryCount = 5);
sb.AddServiceBusTopic("events").AddServiceBusSubscription("audit");

builder.AddProject<Projects.MyApi>("api").WithReference(sb).WithComputeEnvironment(acaEnv);
```

`WithReference` of the namespace, a queue, a topic or a subscription grants the hosting compute environment's identity *Azure Service Bus Data Owner* on the namespace (the official default); `WithRoleAssignments(sb, AzureServiceBusRole.AzureServiceBusDataSender, ...)` replaces it. The namespace name is auto-generated by the azure-native provider. Not ported: `RunAsEmulator` (the Service Bus emulator) and its configuration APIs.
