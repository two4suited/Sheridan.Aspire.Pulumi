# Sheridan.Aspire.Pulumi.Azure.Kusto

_Kusto (Azure Data Explorer)_ — part of [Sheridan.Aspire.Pulumi](../../README.md).

`Sheridan.Aspire.Pulumi.Azure.Kusto` ports `Aspire.Hosting.Azure.Kusto`. `builder.AddPulumiKustoCluster("kusto")` (aliases `AddPulumiAzureKustoCluster`, `AddPulumiKusto`) provisions an `azure-native:kusto:Cluster` with the official defaults (`Standard_E2a_v4`, tier Standard, capacity 2, `aspire-resource-name` tag) and `AddReadWriteDatabase(name, databaseName?)` adds `azure-native:kusto:ReadWriteDatabase` resources. Outputs: `ClusterUri`, `Name`, `Id`. The cluster connection string is `Data Source=<clusterUri>` and a database's adds `;Initial Catalog=<db>`, so `.WithReference(db)` yields `ConnectionStrings__<db>`. Compute environments hosting a referencing app get the database `User` principal role (`DatabasePrincipalAssignment`, principal type `App`) on every database, as in the official `-roles` module.

```csharp
var kusto = builder.AddPulumiKustoCluster("kusto")
    .WithPulumiStack(azureStack)
    .ConfigureInfrastructure(infra => infra.KustoCluster.Set("enableStreamingIngest", true));
var telemetry = kusto.AddReadWriteDatabase("telemetry").WithCreationScript(".create table T (A:string)");

builder.AddProject<Projects.MyApi>("api").WithComputeEnvironment(acaEnv).WithReference(telemetry);
```

`ConfigureInfrastructure` follows the overlay pattern in `../../docs/provisioning.md` (roots `KustoCluster`, `Databases`; azure-native property names). `WithSku(name, tier, capacity)` is an addition. `WithCreationScript` provisions an `azure-native:kusto:Script` (the official Bicep does not; it runs the script against the emulator). The cluster name is auto-generated by the provider. Not ported: `RunAsEmulator`/`WithHostPort` (Kusto emulator container), Kusto Explorer dashboard commands and health checks.
