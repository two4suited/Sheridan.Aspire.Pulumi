# Sheridan.Aspire.Pulumi.Azure.AppConfiguration

_App Configuration_ — part of [Sheridan.Aspire.Pulumi](../../README.md).

`builder.AddPulumiAppConfiguration("appconfig")` (project `Sheridan.Aspire.Pulumi.Azure.AppConfiguration`; alias `AddPulumiAzureAppConfiguration`) is the Pulumi equivalent of `AddAzureAppConfiguration`: a standard-SKU `azure-native:appconfiguration:ConfigurationStore` with local auth disabled and the `aspire-resource-name` tag (same shape as the official Bicep), outputs `appConfigEndpoint`, `name`, `id`. The endpoint is the connection string, so `.WithReference(appConfig)` yields `ConnectionStrings__appconfig`. The store name is auto-generated by the azure-native provider.

```csharp
var appConfig = builder.AddPulumiAppConfiguration("appconfig")
    .WithPulumiStack(azureStack)
    .RunAsEmulator()                                   // local emulator container (run mode only)
    .ConfigureInfrastructure(i => i.AppConfigurationStore.Set("softDeleteRetentionInDays", 7));

builder.AddProject<Projects.MyApi>("api")
    .WithComputeEnvironment(acaEnv)
    .WithRoleAssignments(appConfig, AzureAppConfigurationRole.AppConfigurationDataReader)  // optional; default is Data Owner, as in the official package
    .WithReference(appConfig);
```

Also supported: `PublishAsExisting`/`AsExisting`, and the emulator options `WithDataVolume`, `WithDataBindMount`, `WithHostPort`, `WithAnonymousAccess`. `ConfigureInfrastructure` exposes the `AppConfigurationStore` root (azure-native property names). Not ported: private endpoints and the polyglot (ATS) projections.
